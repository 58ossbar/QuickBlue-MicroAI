# QuickBlue-MicroAI Docker 一键部署说明（运维手册）

> 适用：QuickBlue-MicroAI（后端，MySQL 版）+ QuickBule-MicroAI-web（前端），Docker Compose 编排。
> 全部 12 个服务：11 个常驻容器 + `nacos-init` 一次性初始化任务（完成后自动退出）。
> 所有命令默认在 `deploy` 目录下执行；`docker compose` 等价于 `docker-compose`（新版用空格）。
> **宿主机只需安装 Docker（含 compose 插件）**——后端在容器内用 Maven 打包，无需 JDK/Maven。

---

## 一、目录结构

```text
QuickBlue-MicroAI/                        # 项目根（前后端两仓库同级）
├── QuickBlue-MicroAI/                    # 后端源码
│   ├── docker/Dockerfile.app            # ★ 后端通用镜像构建文件（compose 引用）
│   ├── .dockerignore                    # 后端构建上下文排除清单
│   ├── database/mysql/                  # 数据库初始化 SQL（01~05，compose 挂载为 /sql）
│   ├── nacos_config/                    # Nacos 配置模板（compose 挂载为 /config）
│   └── ...
├── QuickBule-MicroAI-web/               # 前端源码（Vue 3）
│   ├── docker/Dockerfile.frontend       # ★ 前端镜像构建文件
│   └── .dockerignore
└── deploy/                              # ★ 部署目录（所有命令都在这里执行）
    ├── docker-compose.yml               # 服务编排
    ├── .env                             # 环境变量（密码/密钥，勿提交 git）
    ├── .env.example                     # 环境变量模板
    ├── build.sh                         # 构建部署（--all 全量 / 指定服务）
    ├── docker/
    │   ├── nginx/nginx.conf             # 前端 Nginx 配置（/api 反代网关）
    │   └── init/
    │       ├── init-mysql.sh            # MySQL 首启自动建库 + 导入 01~05
    │       └── import-nacos.py          # Nacos 配置导入（nacos-init 容器执行）
    └── scripts/
        ├── start-staged.sh              # 分层启动（Linux/Mac）
        └── start-staged.bat             # 分层启动（Windows）
```

> 注意：compose 中所有相对路径以 `deploy/` 为基准解析，
> `../database/mysql` = 后端仓库的 `database/mysql/`，`../../QuickBule-MicroAI-web` = 前端仓库根。
> 服务器上请保持「后端仓库 + 前端仓库 + deploy 同级」的相对结构。

## 三、首次部署（3 条命令）

```bash
cd deploy

# 1. 准备环境变量（生产环境务必修改 MYSQL_ROOT_PASSWORD / REDIS_PASSWORD / SM4_ENCRYPT_KEY）
cp .env.example .env

# 2. 全量构建 + 分层启动（首次约 20~40 分钟：下载镜像 + 容器内 Maven 打包）
bash build.sh --all

# 3. 浏览器访问 http://服务器IP:8088 完成安装向导
#    （Windows 下用 Git Bash 执行；或分步：docker compose build && scripts\start-staged.bat）
```

**自动化完成的事项**：

- MySQL 首次启动自动执行 `init-mysql.sh`：建 4 个业务库 + 导入 `01~05` 全部表结构与种子数据
- `nacos-init` 自动创建 `QuickBlue-dev` 命名空间，导入 `nacos_config/common + services` 全部配置
- 各微服务自动注册 Nacos → 网关就绪 → 前端可访问

## 四、日常操作

### 1. 启动 / 停止

```bash
bash scripts/start-staged.sh     # 整机重启后一键拉起（镜像已存在时）
docker compose stop              # 优雅停止（保留容器与数据）
docker compose down              # 删除容器（保留数据卷）
docker compose down -v           # ⚠️ 彻底重置（连数据卷一起删，下次启动重新初始化）
```

### 2. 发布改动

```bash
bash build.sh system frontend    # 只重建/重启指定服务（支持短名，可多个）
bash build.sh --all              # 全量重建 + 分层启动
```

### 3. 单个服务

```bash
docker compose ps                        # 状态总览（含健康状态）
docker compose logs -f quickblue-gateway # 实时日志
docker compose restart quickblue-system  # 重启（Nacos 改配置后用它生效）
```

### 4. 可选：本地嵌入模型（完全离线的知识库向量化）

```bash
bash build.sh --all && bash scripts/start-staged.sh --profile ollama
```

`ollama-init` 会自动拉取 `nomic-embed-text`（约 270MB）。随后在管理后台 AI 模型配置中
把嵌入模型地址填 `http://服务器IP:11434`。不用时不启用该 profile 即可。

## 五、常见问题

| 现象 | 排查 |
|------|------|
| 服务卡在 unhealthy | `docker compose logs --tail 200 <服务名>`，数据库/Redis/Nacos 未通是最常见原因 |
| MySQL 初始化失败 | `docker compose logs mysql`；确认 `database/mysql/01~05` 五个脚本齐全 |
| Nacos 导入失败 | `docker compose logs nacos-init`；内网关闭鉴权时 `.env` 的 `NACOS_USERNAME/PASSWORD` 必须留空 |
| 登录失败 | 检查 `SM4_ENCRYPT_KEY` 与前端 `src/lib/encrypt.js` 的 `SM4_KEY` 是否一致 |
| 端口被占用 | 修改 compose 的 `ports` 映射（如 `"3307:3306"`），并同步改 `.env` 中 `MYSQL_PORT=3307` |
| 前端页面 API 404 | 前端走 nginx 同域代理 `/api` → 网关；改过端口时同步检查 `docker/nginx/nginx.conf` |

## 六、注意事项

1. **`.env` 不要提交到 git**；修改后需 `docker compose up -d` 重建对应容器生效；
2. 服务器防火墙按需放行：`8088`（必）、`8080`、`8848`；`3306/6379/11434` 仅调试时放行，生产建议不映射；
3. **MySQL 数据在 `quickblue-mysql-data` 卷**，`docker compose down` 不会丢数据，
   `down -v` 会；定期备份：
   ```bash
   docker compose exec mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --all-databases --routines' > backup-$(date +%F).sql
   ```
4. **健康探针**：各后端走 `/actuator/health/readiness`（Spring Boot 4 默认启用），
   就绪前容器为 `unhealthy`，依赖它的服务不会启动；
5. 生产环境建议：改掉所有默认密码、开启 Nacos 鉴权、限制容器端口映射。
